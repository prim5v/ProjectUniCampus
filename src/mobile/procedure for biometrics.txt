                Server

        |                   |
 Access Token        Refresh Token Hash
 (15 min)            (database)
        |
        |
 React Native App
        |
 ------------------
 |                |
SecureStore    Biometrics
 |                |
Refresh Token   Face/Fingerprint

This is close to how banking apps handle "login once, unlock forever".

One thing I'd avoid: creating your own PIN system inside the app unless you have a strong reason. 
Device PIN/biometrics are already backed by secure hardware. A custom PIN means you now have to handle hashing, brute-force protection,
 lockouts, recovery, and secure storage yourself. For a student ID platform, using the device security model is the better choice.

Step 2 — Add Android native code

Example:

android/src/main/java/com/unicampus/security/SecurityModule.kt
package com.unicampus.security

import android.content.Context
import androidx.security.crypto.EncryptedSharedPreferences
import androidx.security.crypto.MasterKeys
import com.facebook.react.bridge.*

class SecurityModule(
    reactContext: ReactApplicationContext
): ReactContextBaseJavaModule(reactContext) {


    override fun getName(): String {
        return "UniCampusSecurity"
    }


    @ReactMethod
    fun saveRefreshToken(
        token: String,
        promise: Promise
    ) {

        try {

            val prefs = EncryptedSharedPreferences.create(
                "unicampus_secure",
                MasterKeys.getOrCreate(MasterKeys.AES256_GCM_SPEC),
                reactApplicationContext,
                EncryptedSharedPreferences.PrefKeyEncryptionScheme.AES256_SIV,
                EncryptedSharedPreferences.PrefValueEncryptionScheme.AES256_GCM
            )


            prefs.edit()
                .putString("refresh_token", token)
                .apply()


            promise.resolve(true)


        } catch(e: Exception){

            promise.reject(
                "SAVE_FAILED",
                e.message
            )
        }
    }



    @ReactMethod
    fun getRefreshToken(
        promise: Promise
    ){

        try {

            val prefs = EncryptedSharedPreferences.create(
                "unicampus_secure",
                MasterKeys.getOrCreate(MasterKeys.AES256_GCM_SPEC),
                reactApplicationContext,
                EncryptedSharedPreferences.PrefKeyEncryptionScheme.AES256_SIV,
                EncryptedSharedPreferences.PrefValueEncryptionScheme.AES256_GCM
            )


            val token =
                prefs.getString("refresh_token", null)


            promise.resolve(token)


        } catch(e: Exception){

            promise.reject(
                "READ_FAILED",
                e.message
            )
        }
    }
}

Now your JS can call:

await UniCampusSecurity.saveRefreshToken(token);

For UniCampus specifically, I would actually create three packages:

@unicampus/security
    |
    ├── Secure token storage
    ├── Biometrics
    ├── Device keys


@unicampus/hce
    |
    ├── NFC Host Card Emulation
    ├── APDU handling
    ├── Digital ID broadcasting


@unicampus/crypto
    |
    ├── RSA signing
    ├── Payload encryption
    ├── Signature verification

That separation mirrors how large identity/security platforms are structured. It also means your HCE work can mature independently without touching your authentication system.
